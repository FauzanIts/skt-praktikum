B.  LANDASAN TEORI 
B.1  Mengapa Harus Dua Host 
Seluruh materi mata kuliah ini berdiri di atas satu premis: sistem terdistribusi tersusun dari elemen 
komputasi yang otonom. Masing -masing punya jam, memori, dan kendali sendiri, tetapi bagi 
penggunanya tampak sebagai satu sistem yang koheren. Premis itu mudah diucapkan, tetapi sulit 
dirasakan bila seluruh percobaan dijalankan di satu laptop. 
Menjalankan semua container di satu host memang lebih praktis. Namun tiga gejala inti mata kuliah ini 
jadi tidak bisa diamati. RTT jaringan mendekati nol sehingga tidak terukur. Partisi jaringan hanya bisa 
ditiru lewat konfigurasi, bukan dialami. Yang pali ng menentukan, seluruh proses berbagi satu jam 
sistem, sehingga clock skew hilang sama sekali. Padahal clock skew adalah alasan keberadaan seluruh 
materi sinkronisasi pada Pertemuan 5. 
Dengan dua laptop yang terhubung melalui jaringan ad -hoc, ketiganya hadir secara nyata. Anda bisa 
mengukur RTT dalam milidetik. Anda bisa memutus koneksi dengan mematikan hotspot, lalu 
menyaksikan sebagian sistem tetap hidup sementara sebagian lain tidak t erjangkau. Anda juga bisa 
membuktikan sendiri bahwa jam kedua laptop tidak pernah persis sama. Jadi penyiapan lingkungan 
pada modul ini bukan pekerjaan administratif sebelum praktikum dimulai. Penyiapan inilah 
praktikumnya. 
B.2  Virtual Machine dan Container 
Sebuah node dalam sistem terdistribusi tidak harus berupa komputer fisik. Node bisa berupa virtual 
machine atau container, selama ia punya identitas jaringan sendiri dan menjalankan prosesnya sendiri. 
Keduanya menyediakan pemisahan, tetapi dengan cara dan ongkos yang berbeda. 
Virtual machine berjalan di atas hypervisor dan memuat guest OS yang lengkap. Pemisahannya kuat 
karena setiap virtual machine punya kernel sendiri, tetapi ongkosnya besar: ukurannya dalam gigabyte 
dan waktu mulainya puluhan detik. Container mengambil jalan lain. Ia berbagi kernel host OS dan hanya 
membungkus aplikasi beserta library yang dibutuhkannya. Akibatnya container jauh lebih ringan dan 
mulai dalam hitungan detik, dengan pemisahan yang lebih longgar.

B.3  Alamat, Port, dan Batas localhost 
Service yang dijalankan di satu laptop biasanya cukup diakses melalui alamat 127.0.0.1 atau nama 
localhost. Alamat itu adalah alamat loopback: ia selalu menunjuk ke laptop yang sedang Anda pakai dan 
tidak pernah keluar dari laptop tersebut. Selama semua komponen berada di satu laptop, ini tidak 
menimbulkan masalah. 
Begitu service harus dijangkau dari host lain, alamat loopback tidak lagi memadai. Service harus di-bind 
ke alamat yang bisa dijangkau dari jaringan. Alamat 0.0.0.0 berarti "listen di seluruh network interface 
yang dimiliki host ini", sehingga request dari  laptop seberang bisa diterima. Inilah kekeliruan paling 
sering pada praktikum semacam ini: service berjalan tanpa error dan terbuka normal dari  laptop 
sendiri, tetapi tidak pernah bisa diakses dari laptop pasangannya.

B.4  RTT dan Clock Skew 
Round-trip time atau RTT adalah selisih antara saat sebuah request dikirim dan saat balasannya 
diterima. Keduanya diukur dengan jam pengirim. Karena diukur oleh satu jam yang sama, angka ini bisa 
dipercaya. Pada jaringan ad -hoc antarlaptop, nilainya biasan ya beberapa milidetik: kecil, tetapi jelas 
bukan nol. 
Persoalannya lain ketika kita ingin tahu kapan tepatnya penerima memproses pesan tersebut. Waktu 
yang dicatat penerima berasal dari jam penerima, dan jam kedua laptop tidak pernah persis sama. 
Selisih itu disebut clock skew. Protokol sinkronisasi waktu seperti NTP bisa memperkecilnya, tetapi 
tidak pernah menghilangkannya. Pada jaringan ad -hoc tanpa akses internet, sinkroni sasi itu bahkan 
mungkin tidak berjalan sama sekali.

C.6  Echo Service Lintas Host 
Selanjutnya Anda membangun echo service sendiri yang mengembalikan identitas host dan waktu 
menurut jamnya. Output inilah yang nanti dipakai untuk mengukur clock skew. Di Laptop A, buat folder 
echo-service di dalam repositori kelompok skt-praktikum, lalu buat file berikut di folder itu. 
import json, socket, time 
from http.server import BaseHTTPRequestHandler, HTTPServer 
  
  
class Penangan(BaseHTTPRequestHandler): 
    def do_GET(self): 
        data = { 
            "host": socket.gethostname(), 
            "waktu_unix": time.time(), 
            "waktu_lokal": time.strftime("%H:%M:%S"), 
        } 
        badan = json.dumps(data).encode("utf-8") 
        self.send_response(200) 
        self.send_header("Content-Type", "application/json") 
        self.send_header("Content-Length", str(len(badan))) 
        self.end_headers() 
        self.wfile.write(badan) 
  
    def log_message(self, *args): 
        pass 
  
  
if __name__ == "__main__": 
    # 0.0.0.0 berarti listen di seluruh network interface, 
    # bukan hanya di localhost. Lihat kembali Gambar 1.2. 
    HTTPServer(("0.0.0.0", 8000), Penangan).serve_forever()

C.7  Mengukur RTT dan Clock Skew 
Bagian ini adalah inti modul. Program berikut dijalankan di Laptop B dan menghubungi echo service di 
Laptop A sebanyak tiga puluh kali. Untuk setiap request, program mencatat RTT, lalu memperkirakan  
clock skew dengan membandingkan waktu yang dilaporkan Laptop A terhadap titik tengah antara saat 
kirim dan saat terima. Perkiraan itu memakai asumsi bahwa perjalanan pergi dan pulang memakan 
waktu yang kurang lebih sama. 
Alamat Laptop A tidak ditulis di dalam kode. Alamat itu diberikan sebagai argumen saat program 
dijalankan, sesuai aturan pada B.3.

import json, statistics, sys, time, urllib.request 
  
if len(sys.argv) != 2: 
    print("cara pakai: python ukur.py http://<alamat-Laptop-A>:8080") 
    sys.exit(1) 
  
SASARAN = sys.argv[1]  # alamat Laptop A diberikan saat program dijalankan 
JUMLAH = 30 
rtt, skew = [], [] 
  
for i in range(JUMLAH): 
    t1 = time.time() 
    with urllib.request.urlopen(SASARAN, timeout=5) as r: 
        data = json.loads(r.read().decode("utf-8")) 
    t4 = time.time() 
    rtt.append((t4 - t1) * 1000) 
    tengah = (t1 + t4) / 2  # perkiraan waktu lokal saat Laptop A menjawab 
    skew.append((data["waktu_unix"] - tengah) * 1000) 
    time.sleep(0.2) 
  
rtt.sort() 
print("jumlah pengukuran :", JUMLAH) 
print("RTT p50           : %.2f ms" % statistics.median(rtt)) 
print("RTT p95           : %.2f ms" % rtt[int(0.95 * JUMLAH) - 1]) 
print("RTT min           : %.2f ms" % rtt[0]) 
print("RTT maks          : %.2f ms" % rtt[-1]) 
print("clock skew (rata) : %.2f ms" % statistics.mean(skew))
